# 篮球比赛统计系统
这是一个使用 Vue 3 和 Vite 开发的篮球比赛统计系统，可以记录比赛数据、球员数据，并支持导出为 Excel 格式。

## 功能

- 球员管理：添加/移除球员，设置球员号码和球队
- 比赛控制：开始/暂停比赛，节次控制
- 数据记录：记录得分、犯规、换人等操作
- 数据统计：计算球员上场时间、得分、犯规和正负值
- 数据导出：支持导出原始数据库和 Excel 格式数据
- 数据导入：支持导入之前导出的数据库

## 数据存储

系统使用浏览器的 IndexedDB 作为本地数据库，所有数据都保存在本地，并支持导入导出功能。

## 战力候选模型与本地回测

当前使用 `src/utils/ratingModel.js` 的 v5 混合模型。技术统计先按“近期 60%、个人全季 40%”混合，近期最多取每位球员最近 8 次实际出场，再独立控制近期样本可信度。年度表格中的基础统计仍展示全季数据。

全季与近期分别计算样本系数 `c = min(场数/(场数+3), 分钟/(分钟+150))`。实际近期占比为 `0.6 * min(1, c近期/c全季)`，剩余占比回到个人全季指标；技术统计外层仍只应用一次全季可信度，避免重复收缩。同一批近期与全季记录不当作两份独立证据：两者相同时混合不改变表现。可信度是启发式样本权重，不是准确率或统计置信区间。

场均得分、收缩后的得分率、正负值、场均分钟和收缩后的犯规率分别混合，再用训练期联盟分布标准化。技术统计与全季 Elo/调整胜率的合成权重仍为 80%/20%。保留时长权重减少三分之一、强度差保留 50%、显示中心 67、概率温度 2；不加入同队基线、RAPM、额外近期奖励或按姓名调分。页面比分模拟仍独立按全季得分速率估算。

```bash
npm test
npm run backtest:ratings -- --year=2026
```

旧版基线来自 Git 提交 `d8b2579`。每场只使用此前日期的比赛训练，前 8 场积累历史；原中间 21 场用于开发、最后 10 场用于时间留出。初版 v2 选定的概率温度 2 在后续版本中固定沿用。由于这些比赛及球员排名已参与反馈和模型选择，目前所有结果只作回顾性对照，不称为独立验证。

输出为 `reports/rating-backtest-2026/report.html` 和 `results.json`，包括全部球员/常规球员排名、逐场预测、近期与全季可信度、实际近期占比、参数及源数据哈希。`initial-candidate-*` 保存 v2，`previous-candidate-*` 与 `snapshots/ratingModel-v3.js` 保存 v3，`recent-candidate-*` 与 `snapshots/ratingModel-v4.js` 保存 v4。旧版本从冻结算法重新计算并核对原结果，不用新模型中间值冒充旧版。离线诊断脚本仍基于冻结 v3，保持原试算可复现。

截至 2026-11-16，39 场中滚动评价 31 场：线上旧版 18/31、Brier 0.2356；v4 为 19/31、0.2386；v5 为 19/31、0.2407。最后 10 场：旧版 6/10、0.2370；v4 为 7/10、0.2345；v5 为 7/10、0.2369。混合版命中数与 v4 相同，概率误差略高，未证明预测更准。

回测以最终导出名单为给定条件（包括 DNP），不读取待预测比赛的时长、得分或正负值。历史修正版用于回放，无法复原原日期的数据版本与赛前名单；分差采用开发段单独标定的辅助指标，不冒充页面随机比分模拟。缺席较久者使用其最近出场记录，未自动假设能力下降或进步。回测报告保留分析时的结果，实际部署状态以 GitHub Pages 的对应提交为准。

## 使用说明
1. 首先添加两队球员，可以使用预设球员池或手动添加
2. 点击"开始比赛"按钮开始记录比赛数据
3. 使用替补区域上下场球员（每队最多5人同时在场）
4. 使用得分和犯规按钮记录相应数据
5. 比赛结束后可以导出数据进行分析

## 公司篮球赛

- 登录页选择“公司比赛”，或从日常比赛主页点击“公司比赛”。实时统计入口为 `#/company`，免登录历史入口为 `#/company/history`。
- 选择主队和客队，点击“载入对战名单 / 新建比赛”，再安排双方首发。名单来自《篮球赛报名信息汇总.xlsx》的“汇总报名”，只取“篮球队伍”，共 6 队、86 人，号码保留为字符串（含 0 号）。队名使用汇总页写法。名单预览、上场区与替补席均按球衣号码数值升序显示，换人后自动排序。
- 公司赛沿用得分、犯规、上下场、节次、上场时间、正负值、比分走势以及 JSON / Excel 导出。公司赛使用独立的 `CompanyBasketballStatsDB`，日常比赛继续使用原数据库。
- 比赛结束后点击“结束并归档”，记录进入公司赛历史比分。重复归档更新同一场；新建比赛会生成不同的比赛 ID，同日多场互不覆盖。清除当前比赛不会删除已归档记录。
- 本机归档存在当前浏览器，清理浏览器数据会丢失，建议从历史卡片导出 JSON。可用“导入公司赛 JSON”恢复，再归档。
- 上场时间只在比赛运行时累计。休息应点“暂停比赛”；公司赛切换节次会自动暂停，下一节需手动开始。刷新或恢复页面保持暂停，不补算离线时间。
- 公司赛历史按“分:秒”显示上场时间，详情中的两队球员默认按实际总上场时间从长到短排列，同时间按号码升序。经核实修正的比赛用 `revision` 标记版本，更新的公开修正版优先于旧本机归档；修正区间、依据和逐人扣减保存在 `timingCorrections`，原始事件明细保留。
- 公司赛和日常比赛的历史详情底部显示比分走势，按该场得分明细绘制双方曲线、最大分差和得分球员提示；无得分明细时显示空状态。
- 实时和历史比分走势顶部按事件时间展示暂停（橙色三角）与换人（绿色圆圈）节点，可分别开关。悬停预览、点击锁定时刻；固定详情栏在宽屏位于曲线右侧，窄屏位于下方，显示该时刻的比分、领先球队、分差、事件和双方在场名单（含号码）。图中参考线连接该时刻的两队得分，详情不覆盖曲线。密集节点保留每条记录，比分与名单取本组最后时刻。

### 公司赛公开历史目录

公司赛单独使用 `public/data/company/{年份}/`，与日常比赛的年度数据目录分开。

将导出的 `company_basketball_日期_比赛ID.json` 放入对应年份目录，并在该目录的 `matches.json` 的 `files` 数组中添加文件名，例如：

```json
{
  "files": ["company_basketball_2026-10-27_比赛ID.json"],
  "removedMatchIds": [],
  "matchStages": {"比赛ID": "小组赛"}
}
```

部署后，所有设备可从公司赛历史入口查看公开记录；未发布前仅当前浏览器可见。本机与公开目录存在同一比赛 ID 时，优先显示本机修正版。报名源文件中的部门、尺码和对接人未导入网站。

`matchStages` 按比赛 ID 标注赛程阶段，历史卡片和详情均显示；同 ID 的本机归档也采用该阶段。2026 年 11 月 5 日两场为“半决赛”，此前六场为“小组赛”。阶段保存在目录索引中，原始比赛 JSON 不变；未配置阶段的新记录不自动归类。

测试比赛在 JSON 的 `game[0]` 中设置 `isTest: true`，历史卡片和详情会显示“测试赛”，导出备份也保留此标记。

移除已发布记录时，删除对应 JSON 和 `files` 中的文件名，并把其比赛 ID 加入 `removedMatchIds`，避免旧的本机归档再次出现在历史列表。旧版只含文件名数组的目录仍可读取。
